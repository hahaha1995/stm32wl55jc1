Letter Shell 工作原理 · 可视化

单字节中断接收 → 环形缓冲 → shellTask 解析执行 → 阻塞发送回显

STEP 0 / 10 shell 空闲，等待输入（演示命令：hello）
硬件/中断路径 (RX) 数据缓冲/任务 解析器 命令表/执行 输出路径 (TX)

为什么用「单字节中断 + 环形缓冲」

  • 每字节一次中断，实现简单，不依赖 DMA
  • ISR 只做入队 + 重新武装，耗时 < 1µs
  • 环形缓冲 256 B 容纳突发输入，任务慢时不丢字符

解析器是逐字符状态机

  • 普通字符进编辑缓冲并回显；退格/删除回退光标
  • Tab 触发补全；回车触发 shellExec() 解析执行
  • 编辑缓冲与命令表解耦，历史命令单独存储

命令表来自链接段

  • `SHELL_EXPORT_CMD` 把命令记录放进 shellCommand 段
  • 链接脚本 `_shell_command_start/_end` 界定范围，无需手写表
  • 新增命令 = 加一个宏，零注册代码

中断/任务上下文分离

  • ISR 内禁止 FreeRTOS API（只做纯 C 操作）
  • 阻塞发送/解析/执行全部在 shell 任务上下文
  • shell 任务优先级低（idle+1），不抢占业务
