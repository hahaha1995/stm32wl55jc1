STM32WL55JC1 (NUCLEO-WL55JC1) · Letter Shell · ROM Bootloader @ 0x1FFF0000

STEP 0 / 10 MCU 正常运行，shell 等待输入
Flash 应用区（用户代码） SRAM .bootflag（复位保留） ROM Bootloader（工厂固化） UART 通道（USART2 / LPUART1 @ PA2/PA3） 复位 / 跳转动作

为什么用「标志 + 复位」

  • IWDG 无法软件停止：启动后只能喂狗，不能关闭，直接跳转会被看门狗复位
  • 系统复位是清除 IWDG 的唯一途径，复位后 ROM 不会启动它
  • 复位后外设状态干净，跳转无需清理 UART / 中断

.bootflag 段为什么能保留

  • 放在 .bss 之后且为 NOLOAD，startup 的零初始化不会碰到它
  • 不参与 .data 拷贝，复位后值保留
  • 魔数 0x4C53424C = ASCII "LSBL"，误触发概率 1/2³²

为什么跳 ROM 而不是改 MEMRMP

  • 直接读 0x1FFF0000 向量表并跳转，不改 boot 配置
  • 下载完成 -rst 后必定回到 Flash 应用，不依赖 remap 复位行为

ROM 为什么「停得住」

  • ROM 固件死循环等待同步字节 0x7F（AN3155），收到回 0x79 ACK
  • ROM 的 USART2 @ PA2/PA3 与板载 VCP 及 shell 引脚完全一致，不用改线
