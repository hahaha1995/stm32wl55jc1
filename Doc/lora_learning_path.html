# 学习目标 对应步骤（怎么做） 工具 / 材料 验证标准（做到什么算完成）

B · 关键概念速查OTAA 三步 / 两种时间同步 / 双核架构 / US915 要点点击展开

OTAA 入网三步

  • ① JoinRequest：带上 DevEUI/AppEUI + MIC(AppKey 派生)
  • ② JoinAccept：服务器下发加密帧，含 DevAddr
  • ③ 派生密钥：本地算出 NwkSKey/AppSKey，开始上行

两种时间同步

  • DeviceTimeReq/Ans：Class A 零星请求（1.0.4+ / TS002）
  • Class B Beacon：服务器每 128s 广播，设备周期性校时
  • Class B 的定时接收(PingSlot)依赖 Beacon 校准

双核架构（关键）

  • CM4：跑 LoRaWAN 协议栈 + 应用（LoRaMac.c 等）
  • CM0+：跑 ST 官方 RF 固件（SX126x 底层）
  • 两块固件都要烧，通过 IPCC/SHCI 协作

US915 与实验室网关配合要点

  • 区域宏 LORAMAC_REGION_US915（902–928 MHz，8×125k 子带 + 8×500k）
  • Join 前确认网关监听通道与设备子带一致（常见 sub-band 1/2）
  • TTN/ChirpStack 应用选择 US915；上行 DR0–DR5、下行 DR8–DR13
  • ⚠️ 902–928 MHz 在中国属非授权频段，仅限实验室合规环境使用
C · AppEUI / AppKey 获取与使用三个 ID 从 TTN 拿 → 写进固件 → 与网关无关点击展开
ID 长度 谁生成 作用 / 注意
DevEUI 8 字节 TTN 生成(或设备出厂 ID) 标识"这台设备"；固件中 AT+DEVEUI 查看/设置
AppEUI (JoinEUI) 8 字节 TTN 生成(或自己指定) 标识"加入哪个应用"；必须与固件 AT+APPEUI 一致
AppKey 16 字节 TTN 生成(或自己指定) 根密钥：派生 NwkSKey/AppSKey、校验 MIC；抄错一个字符就永远 JOIN 不上

② 写进固件的两种方法
// 方法 A: 改源码（LoRaWAN_End_Node 示例 se_identity.c / app_conf）
#define DEMO_APP_EUI  { 0xXX,0xXX,... }   /* 8 字节 = TTN 的 JoinEUI */
#define DEMO_APP_KEY  { 0xXX,0xXX,... }   /* 16 字节 = TTN 的 AppKey */
#define DEMO_DEV_EUI  { 0xXX,0xXX,... }   /* 8 字节 = TTN 的 DevEUI */

// 方法 B: AT 命令（无需重新编译，AT_Slave 支持）
AT+DEVEUI=...      AT+APPEUI=...      AT+APPKEY=...
AT+DEVEUI=?        AT+APPEUI=?        AT+APPKEY=?   // "?" 查询确认
⚠️ 常见坑： ① TTN 频段 plan 必须与网关一致选 US 915，选错会被 NS 丢弃； ② AppKey 抄错 → JoinRequest 发出去但 TTN 一直不响应（MIC 校验失败）； ③ 设备详情页 AppKey 被隐藏时点 Show key； ④ 网关不需要这三个值——网关只配 Gateway EUI + Server Address，AppKey 只存在于"设备 ↔ TTN"之间；泄露即等于别人可以仿冒你的设备。
